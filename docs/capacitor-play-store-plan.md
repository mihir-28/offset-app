# Offset: PWA to Android / Google Play Plan

## Goal

Package Offset as an Android app using Capacitor and publish it through Google Play.

Recommended production architecture:

```text
Next static export -> out/
        -> Capacitor Android WebView
        -> Firebase Auth + Firestore
        -> signed Android App Bundle (.aab)
        -> Google Play Console
```

Use bundled web assets, not a production `server.url` remote-WebView configuration. Bundling provides a faster and offline-capable app shell and avoids releasing a thin website wrapper.

## Current-project findings

- App: Next.js 16, React 19, TypeScript, Tailwind.
- PWA assets: `public/site.webmanifest`, `public/sw.js`, PWA install toast.
- Backend: Firebase Authentication and Firestore.
- Auth: Google via Firebase Web `signInWithPopup`.
- Dynamic route: `src/app/statements/[id]/page.tsx`.
- User-facing account creation exists, but account deletion does not.

## Phase 1: Baseline and release identity

1. Create a dedicated conversion branch, e.g. `feature/android-capacitor`.
2. Record current web baseline: Google sign-in, transaction CRUD, statements, offline behavior.
3. Reserve Android package ID:

   ```text
   com.afterthought.offset
   ```

4. Set Android release versioning:

   ```text
   versionName: 1.1.2
   versionCode: 1
   ```

   Increment `versionCode` for every Play upload.
5. Target Android API 36 or later. New Google Play submissions after August 31, 2026 require Android 16 / API 36 or higher.

Exit criteria: web baseline documented and package/version decisions final.

## Phase 2: Enable static export

Capacitor must consume generated web files. Configure Next to emit static files into `out/`.

1. Update `next.config.ts`:

   ```ts
   import type { NextConfig } from "next";

   const nextConfig: NextConfig = {
     output: "export",
     images: { unoptimized: true },
     reactCompiler: true,
   };

   export default nextConfig;
   ```

2. Replace data-dependent dynamic route `/statements/[id]`.

   Recommended route:

   ```text
   /statements/detail?cycleId=<id>
   ```

   Update links, router pushes, navigation, and back behavior. A runtime data-dependent segment cannot be generated by static export without knowing every ID at build time.
3. Check all app routes generate static output successfully.
4. Keep Firebase values as build-time `NEXT_PUBLIC_FIREBASE_*` variables. These are client Firebase identifiers, not server secrets. Do not put Admin SDK credentials or service accounts in the client bundle.
5. Add package scripts:

   ```json
   {
     "build:web": "next build",
     "cap:sync": "npx cap sync android",
     "android": "npx cap open android"
   }
   ```

Exit criteria: one production web build produces `out/`, and all app screens work from static output.

## Phase 3: Add Capacitor Android

Install matching current Capacitor dependencies:

```bash
npm install @capacitor/core
npm install -D @capacitor/cli
npm install @capacitor/android
npx cap init Offset com.afterthought.offset --web-dir out
npx cap add android
```

Create `capacitor.config.ts`:

```ts
import type { CapacitorConfig } from "@capacitor/cli";

const config: CapacitorConfig = {
  appId: "com.afterthought.offset",
  appName: "Offset",
  webDir: "out",
  android: {
    allowMixedContent: false,
  },
};

export default config;
```

Build and run loop:

```bash
npm run build:web
npx cap sync android
npx cap open android
```

Do not set production `server.url`. A temporary HTTPS `server.url` can help prototype but must not be release configuration.

Exit criteria: Android emulator and physical device load bundled `out/` assets.

## Phase 4: Native Android polish

1. Add Capacitor plugins only where needed:

   ```bash
   npm install @capacitor/app @capacitor/splash-screen @capacitor/status-bar
   ```

2. Generate adaptive launcher icon from approved 512px Offset artwork.
3. Configure native splash screen with Offset mark and `#09090B` background.
4. Configure dark status and navigation bars; test display cutouts and safe areas.
5. Implement Android Back behavior:
   - history exists: return to prior web screen;
   - at app root: background app naturally, never show a blank page.
6. Use HTTPS only. Keep Android cleartext traffic disabled.
7. Request no Android permissions unless required by a shipped feature.

Exit criteria: launch has no white flash; system bars, icon, splash, and Back behavior all match app quality.

## Phase 5: Separate browser-PWA and native behavior

Current PWA code registers `public/sw.js` and displays `InstallToast`.

1. Detect native environment using Capacitor:

   ```ts
   import { Capacitor } from "@capacitor/core";

   const isNative = Capacitor.isNativePlatform();
   ```

2. On Android:
   - do not register `sw.js`;
   - do not show browser install prompt/toast;
   - do not depend on web-push service-worker code.
3. Preserve existing PWA registration and install UX for browser users.

Reason: Capacitor already provides installed-app behavior. Keeping browser service-worker caching active in native adds stale-cache and debugging risk.

Exit criteria: browser PWA remains installable; Android never presents an install prompt or service-worker error.

## Phase 6: Native Firebase Google sign-in

Current login calls `signInWithPopup(auth, provider)`. Do not rely on popup auth inside Android WebView.

Implement platform-specific auth:

```text
Browser -> Firebase Web signInWithPopup
Android -> native Google sign-in / Credential Manager -> Firebase credential
```

Tasks:

1. Add Android app `com.afterthought.offset` in Firebase Console.
2. Generate debug and release signing SHA-1 values.
3. Add debug and release SHA-1 values in Firebase Android app settings.
4. Download updated `google-services.json` and place it in `android/app/`.
5. Ensure Google provider is enabled in Firebase Authentication.
6. Add maintained Capacitor Firebase Authentication bridge compatible with installed Capacitor major version.
7. Build an auth adapter instead of scattering platform checks through screens:

   ```text
   signInWithGoogle()
     browser -> existing Firebase Web popup flow
     Android -> native Google token flow
   ```

8. Exchange native Google ID token for Firebase credential/session used by existing Firestore web SDK, or migrate Firebase access behind a shared native/web adapter.
9. Test sign-in, account selection, cancellation, session restore, sign-out, network failure, and first account creation.
10. After enrolling in Play App Signing, add Play app-signing certificate SHA-1 to Firebase too. Local keystore SHA-1 alone does not cover Play-installed builds.

Exit criteria: same Google user receives same Firebase UID and Firestore data on web and Android.

## Phase 7: Firestore and offline validation

Validate actual release build:

- Authenticated Android user may only access own `users`, `cards`, `transactions`, and `statementCycles` documents.
- Existing migration functions remain idempotent.
- Firestore offline persistence loads cached data, queues writes, and syncs on reconnect.
- Airplane-mode test: open cached session, view data, add/edit/delete, reconnect.
- Two-device test: update same card/transaction from web and Android.
- Do not rely on service-worker cache for Firebase offline behavior; Firestore cache owns this concern.

Review `firestore.rules`: `users`, `cards`, and `transactions` currently lack explicit `delete` permission, while `statementCycles` allow deletion. Confirm this matches desired behavior before release.

Exit criteria: no cross-user data access, data loss, or stuck offline write in test matrix.

## Phase 8: Play policy and privacy work

### Account deletion

Google Play requires a deletion path for apps that create accounts.

1. Add visible **Delete account** action in Settings -> Account.
2. Require clear confirmation.
3. Delete user-owned data from `cards`, `transactions`, `statementCycles`, and `users/{uid}` in Firestore batches, then delete the Firebase Authentication account.
4. Keep the collection list in sync with future user-data collections. Do not treat sign-out or account disablement as deletion.
5. Add public deletion support URL/process if requested by Play Console.

### Privacy policy and Data Safety

1. Keep `/privacy` public, HTTPS, and accessible without login.
2. Update policy with:
   - Offset/developer name and contact;
   - Google/Firebase processors;
   - account profile data;
   - user-entered transactions, card balances, buckets, statements;
   - use, retention, and deletion process;
   - security/encryption in transit.
3. Link policy in-app and in Play Console.
4. Complete Play Data Safety form based on shipped behavior, including Firebase SDK data practices.
5. Do not declare guessed answers. Data Safety must match app and privacy policy exactly.

Likely collected data categories to verify before declaration:

- name/email/account identifier;
- financial information user enters into Offset;
- app data stored in Firestore;
- any analytics or crash reporting added before release.

Exit criteria: account deletion works end-to-end and Play declarations precisely match product behavior.

## Phase 9: Release QA

Use a signed release build, not debug only.

| Area | Required checks |
| --- | --- |
| Authentication | First login, cancellation, relaunch, logout, Play-signed build |
| Finance data | Add/edit/delete transaction; cards; buckets; statement calculations |
| Navigation | Every screen; statement detail; Android Back |
| Network | Offline launch; queued writes; reconnect; auth expiry |
| Devices | Small phone; large phone; Android 13-16; cutouts; text scaling |
| PWA split | Browser gets service worker/install UX; Android gets neither |
| Security | No secrets in bundle; HTTPS; least privileges |
| Accessibility | Keyboard; TalkBack labels; tap targets; readable enlarged text |

Start Play internal testing, then closed testing. Resolve auth, crash, ANR, and user feedback before production.

## Phase 10: Build and publish Android App Bundle

1. Create Android upload keystore. Store outside repository; back it up securely.
2. Configure release signing through local properties/environment values. Never commit keystore files or passwords.
3. Build signed release AAB in Android Studio:

   ```text
   Build -> Generate Signed Bundle / APK -> Android App Bundle
   ```

4. Expected artifact:

   ```text
   android/app/build/outputs/bundle/release/app-release.aab
   ```

5. In Google Play Console, create Offset app and add:
   - app category, title, description;
   - application icon, feature graphic, phone screenshots;
   - privacy policy;
   - Data Safety form;
   - content rating, ads declaration, target audience;
   - reviewer access instructions if login required;
   - Play App Signing enrollment.
6. Upload `.aab` to internal test, then closed test, then production.
7. For every update: increase Android `versionCode`, build new AAB, upload.

## Milestones

1. Static export passes.
2. Capacitor Android shell runs bundled assets.
3. Native Firebase Google sign-in works.
4. Native/UI/offline QA passes.
5. Account deletion and policy work complete.
6. Signed AAB reaches internal testing.
7. Closed-test feedback resolved; production rollout starts.
